# Universe Coordinate System

## Overview

The universe uses a **dual coordinate system**: a base X/Y grid for storage and a hierarchical 3-level system (R:Sy:P) for organization and display.

## Grid System

### X/Y Coordinates (Primary Storage)

-   **Grid Dimensions**: Configurable via `config/game.php`

    -   Default: `2000 × 1000` (width × height)
    -   Environment variables: `UNIVERSE_WIDTH` and `UNIVERSE_HEIGHT`
    -   Can be rectangular (not just square)

-   **Coordinate Range**:

    -   X: `0` to `grid_width - 1` (e.g., 0-1999)
    -   Y: `0` to `grid_height - 1` (e.g., 0-999)
    -   Total possible positions: `grid_width × grid_height` (e.g., 2,000,000 positions)

-   **Storage**: Planets store `x` and `y` as integers in the database

### Planet Count

-   **Target**: 15,000 planets (configurable in `UniverseSeeder`)
-   **Distribution**: Clustered with voids for organic appearance
    -   120 clusters with varying sizes/densities
    -   20% void probability (empty regions)
    -   Minimum distance: 1 unit between planets
    -   Starter zone (Region 1-3): 95% habitable, larger cluster

## Hierarchical Coordinate System (Computed)

The hierarchical system is **computed on-the-fly** from X/Y coordinates using `CoordinateService`:

### Structure: `Region:System:Planet`

```
Region (1-20)
  └─ System (1-125)
      └─ Planet (1-17)
```

### Hierarchy Breakdown

-   **20 Regions** - Divide the grid into 20 equal parts
-   **125 Systems per Region** - Divide each region into 125 parts
-   **17 Planets per System** - Theoretical max (not enforced)

### Calculation Method

The `CoordinateService` divides the grid mathematically:

```php
// Example for 2000×1000 grid:
Region size: 2000 / 20 = 100 units wide
System size: 100 / 125 = 0.8 units wide

// Y dimension uses similar calculation:
// Systems stack vertically within regions
```

**Conversion Flow:**

1. X/Y stored in database → `CoordinateService::xyToHierarchical()`
2. Returns: `['region' => 1, 'system' => 7, 'planet' => 12]`
3. Displayed as: `"1:7:12"`

## Coordinate Conversion

### X/Y → Hierarchical (Computed)

**Always computed** - never stored:

-   `Planet::getRegionAttribute()` - Computed from X/Y
-   `Planet::getSystemAttribute()` - Computed from X/Y
-   `Planet::getPlanetAttribute()` - Computed from X/Y
-   `Planet::getCoordinateAttribute()` - Returns full string `"R:Sy:P"`

**Method**: `CoordinateService::xyToHierarchical($x, $y)`

### Hierarchical → X/Y Range (Query)

Used for filtering queries:

-   `CoordinateService::getRegionXyRange($region)` - Returns X/Y bounds
-   `CoordinateService::getSystemXyRange($region, $system)` - Returns X/Y bounds

**Example**: Filter planets in System 1:7

```php
$xyRange = $coordinateService->getSystemXyRange(1, 7);
// Returns: ['x_min' => 700, 'x_max' => 700.8, 'y_min' => 0, 'y_max' => 50]
Planet::whereBetween('x', [$xyRange['x_min'], $xyRange['x_max']])
      ->whereBetween('y', [$xyRange['y_min'], $xyRange['y_max']])
```

## Region & System Naming

### Region Model (`regions` table)

-   Stores: `region`, `name`
-   Generated by `UniverseSeeder::generateRegionAndSystemNames()`
-   Names generated via `UniverseNamingService`
-   Special locations get predefined names (Region 1-5)

### System Model (`systems` table)

-   Stores: `region`, `system`, `name`
-   Generated alongside regions
-   Each system within a region gets a unique name

### Relationship to Planets

-   **No direct foreign key** - relationship via coordinate computation
-   `Region::planets()` - Returns planets via X/Y range query
-   Planets can be queried by region using coordinate ranges

## Distance Calculation

### Euclidean Distance

Distance between planets calculated using X/Y coordinates:

```php
Planet::calculateDistance($x1, $y1, $x2, $y2)
// Returns: sqrt((x2-x1)² + (y2-y1)²)
```

Used for:

-   Fleet travel time calculations
-   Detection range checks
-   Combat range calculations

## Planet Seeding Process

1. **Generate Cluster Centers** (120 clusters)

    - Starter zone cluster at (25, 35) - larger and denser
    - Random positions with minimum separation
    - Varying sizes and densities

2. **Place Planets in Clusters**

    - Normal distribution around cluster center
    - Minimum distance check (1 unit)
    - Collision detection with existing planets

3. **Scatter Additional Planets**

    - If target not reached, fill gaps with scattered planets
    - Random placement with distance checks

4. **Generate Names**
    - Region names for all regions (1-20)
    - System names for all region:system combinations (1-20:1-125)
    - Special locations get predefined names

## Key Points

✅ **X/Y is primary** - All planets stored with X/Y coordinates  
✅ **Hierarchical is computed** - Never stored, always calculated  
✅ **Flexible grid** - Can be rectangular (2000×1000, etc.)  
✅ **Clustered distribution** - 15,000 planets in organic clusters  
✅ **Distance-based** - All distance calculations use X/Y  
✅ **Named regions/systems** - Stored separately, linked via coordinates

## Example

**Planet at X=125, Y=50:**

```
X/Y: (125, 50)

Computed Hierarchical:
- Region: floor(125 / 100) + 1 = 2
- System: floor((125 % 100) / 0.8) + 1 = 32
- Planet: floor(...) + 1 = varies

Result: "2:32:X"
```

**Region Name Lookup:**

-   Query `regions` table: `WHERE region=2`
-   Returns: "Mid Rim" (special name for Region 2)
