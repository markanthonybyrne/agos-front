# Front-End Endgame UX Audit (2025-11-08)

## Scope & Method

- Reviewed gameplay requirements defined in `docs/PLAYER_MANUAL.md`, `docs/TECH_TREE_IMPLEMENTATION_GUIDE.md`, `docs/TechTreeChage.md`, and `docs/COLONIZATION_MECHANICS.md`.
- Inspected core UI composition (`src/App.tsx`, `src/app/store.ts`, slices, and shared hooks) plus feature surfaces under `src/features` and `src/components`.
- Cross-referenced RTK Query endpoints under `src/api/endpoints` to confirm live backend coverage.
- Catalogued outstanding TODOs/TBD logic that block an end-to-end playthrough.

## Executive Summary

- **Shell & data loading** – Routing, auth flow, InitialDataLoader, websocket/tick hooks, and Holopad/Tutorial scaffolding are present and wired to the live API.
- **Core loops** – Resource panels, planet detail hex grid, construction queues, fleet command, market trading, incidents, and messaging views are largely implemented with RTK Query integrations.
- **Critical gaps** – Several “last mile” interactions remain stubbed (`TODO`) and prevent full progression: tech queue actions, exploration/scan context menu, alliance joining/donation balances, achievements progress tracking, coordinate search assistance, and a few map statistics.
- **Next steps** – Implement the missing actions, hydrate the remaining data placeholders, and tighten colonization/visibility UX to satisfy the production-ready expectation outlined in the plan.

## Notable TODO / Stubbed Logic

- Map interactions: “Explore System” and “Scan system” context menu entries are logged only (`src/components/map/GalaxyMap.tsx`, `MapContextMenuProvider.tsx`), blocking discovery UX. Coordinate search suggestions also stubbed.
- Tech tree: queue/start actions unimplemented in both desktop and embedded variants (`TechTreeScreen.tsx`, `TechTreeEmbedded.tsx`), so research cannot be initiated from the tree view.
- Alliances: Joining an alliance and populating donation max/current balances remain TODOs (`AllianceList.tsx`, `DonationDialog.tsx`).
- Achievements: Progress indicators hard-coded placeholder; needs real tracking (`components/premium/AchievementsPanel.tsx`).
- Map v3/v4 stats: Several counts and range calculations are placeholder, affecting alternative map modes (`components/map/v3/UnifiedUniverseMapV3.tsx`, `v4/UnifiedUniverseMapV4.tsx`).
- Construction refresh: `ConstructionQueue` triggers `window.location.reload()` on completion (heavy-handed; prefer targeted refetch).

## Recommended Next Steps (Feeds Phase 2+)

1. **Wire missing actions** – Implement map exploration/scanning triggers, tech queue mutations, alliance join/donation hydration, and achievement progress queries. These are hard blockers for E2E validation.
2. **Enhance colonization UX** – Surface discovery/eligibility states directly in system view sliders and tie into `signalsApi` for remote targets per `COLONIZATION_MECHANICS.md`.
3. **Refine refresh patterns** – Replace global reloads with targeted RTK Query invalidations (construction, tech, map) to keep the single-page feel.
4. **QA pass** – After wiring, run a scripted progression (registration → tutorial → first colony → era unlock → fleets → market → alliances) to confirm all loops operate against the live backend.

This audit completes the first plan task (“Baseline audit of gameplay flows vs docs and catalogue UX/API gaps”) and informs subsequent implementation phases.
